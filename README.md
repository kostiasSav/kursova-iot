# Курсовий проєкт — «Основи інтернету речей та аналітика великих даних»

Репозиторій-заготовка. Тут лежить усе, з чого ви починаєте: шаблон
прошивки, вузол і брокер для дослідження захищеності, конвеєр обробки
даних, детектори, скрипти для реальних даних, дашборди та інструменти
самоперевірки.

Повне завдання, структура пояснювальної записки, перелік класів
інцидентів і система оцінювання — у
[методичних вказівках](docs/metodychni-vkazivky.md).

**Почніть із [покрокового посібника](docs/guide/README.md).** Він веде
через увесь проєкт — від встановлення Python до захисту — з прикладами
команд, очікуваним виводом і знімками екрана. Цей файл — лише коротка
довідка.

---

## Що вам видали

| Файл | Що це |
|---|---|
| `variant_NNN.parquet` | **ваш** набір телеметрії, 4,1–7,3 млн записів |
| `variant_NNN.json` | маніфест: перелік пристроїв і призначений стек |
| `tuning.parquet` | навчальний набір, спільний для всіх |
| `tuning.json` | маніфест навчального набору |
| `tuning_truth.json` | відповіді до навчального набору |

Номер варіанта видає керівник. Файли завантажуються за посиланням із
таблиці призначень.

> Ваш набір даних унікальний. Інциденти у ньому не збігаються з
> інцидентами жодного іншого студента, тому чужі результати вам не
> допоможуть — їх відхилить автоматична перевірка.

## Швидкий старт

Потрібен Python 3.12, 3.13 або 3.14 (на Mac з процесором Intel — 3.13).

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Перевірте, що дані читаються і що маніфест відповідає вашому варіанту:

```bash
python selfcheck.py --findings examples/findings.example.json --data variant_047.parquet --manifest variant_047.json
```

Команда надрукує вашу **картку результатів** — ті самі числа, які мають
стояти одразу після титульного аркуша пояснювальної записки. Файл-приклад
складено для навчального набору (варіант 0), тож повідомлення про
розбіжність номера варіанта й картки тут очікувані.

## Стадія 1. Вузол інтернету речей

1. Створіть новий проєкт ESP32 на [wokwi.com](https://wokwi.com)
   (безкоштовного тарифу достатньо).
2. Замініть вміст на `firmware/sketch.ino`, `firmware/diagram.json`
   та `firmware/libraries.txt`.
3. Впишіть свій номер варіанта і `DEVICE_ID` у налаштуваннях на початку
   файла.
4. Запустіть симуляцію. У послідовному моніторі має з'явитися
   підключення до WiFi, синхронізація часу та публікація повідомлень.

Чотири позначки `TODO` у прошивці — це і є ваше завдання на стадію.

**Дослідження захищеності каналу** виконується на одному комп'ютері в три
кроки: підписка на ваш топік веб-клієнтом MQTT у браузері; запис трафіку
симуляції Wokwi у файл PCAP і його розбір у Wireshark; власний брокер
Mosquitto з TLS і паролем (`broker/`), до якого підключається вузол мовою
Python (`node/node.py`). Покроково — у посібнику, стадія 1.

## Стадія 2. Конвеєр

Пакетне завантаження вашого варіанта у призначене сховище:

```python
from pipeline.storage import open_storage

st = open_storage("duckdb", path="telemetry.duckdb")
rows = st.load_parquet("variant_047.parquet")
ts, val = st.series("temp-03-lob", "temperature")
```

Назву сховища беріть із поля `assigned_stack` у вашому маніфесті —
використання призначеного сховища обов'язкове. Рядок звідти можна
передавати дослівно: `open_storage("DuckDB + Parquet", ...)` теж працює.

Для InfluxDB і TimescaleDB спершу підніміть сервіси:

```bash
docker compose -f pipeline/docker-compose.yml up -d
```

Обов'язкові вимірювання — одна команда:

```bash
python pipeline/measure.py --data variant_047.parquet
```

Потоковий вхід:

```bash
python pipeline/consumer.py --variant 47 --device esp32-047 --minutes 10
```

> Ваш файл містить мільйони записів і поки що вміщується в пам'ять, але
> конвеєр має витримувати й обсяги, які в неї не вміщуються. Тому читайте
> порціями — як це робиться, видно у `storage.py` і `processing/`.

## Стадія 3. Детектори

```bash
python detect/baseline.py --device power-05-mee --metric power_w --evaluate tuning_truth.json
```

Кожен детектор аналізує один ряд (пристрій і показник), друкує
вікна-кандидати, зберігає графік, а з `--evaluate` порівнює результат з
відповідями навчального набору. Призначений вам метод — у
`detect/methods/`; його бібліотеку встановіть окремо (див.
`requirements.txt`).

## Стадія 5. Пошук інцидентів

Знахідки ведіть у таблиці `my_findings.csv`, а `findings.json` зберіть
скриптом:

```bash
python make_findings.py --csv my_findings.csv --data variant_047.parquet --manifest variant_047.json
```

**Перед здачею обов'язково** проженіть його через самоперевірку:

```bash
python selfcheck.py --findings findings.json --data variant_047.parquet --manifest variant_047.json
```

Інструмент перевіряє формат і картку результатів. Він **не** повідомляє,
чи правильні ваші знахідки — відповіді є лише у керівника.

## Що здається

1. пояснювальна записка (25–30 сторінок, картка результатів одразу після
   титульного аркуша; [зразок для заповнення](docs/zrazok-zapysky.docx));
2. цей репозиторій з вашим кодом;
3. `findings.json`;
4. працездатний дашборд;
5. презентація на 7 хвилин.

На захисті вам дадуть **раніше не відомий набір даних** і попросять
запустити ваш конвеєр при комісії:

```bash
python run_all.py --data variant_1NN.parquet --manifest variant_1NN.json --storage <ваше сховище>
```

`--storage` — сховище з **вашого** маніфесту: у маніфесті незнайомого
набору призначено чужий стек. Пошук інцидентів для цього скрипта — ваш файл
`hunt.py` (посібник, крок 8). Переконайтеся заздалегідь, що все запускається не лише на ваших
файлах.
