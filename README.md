# Курсовий проєкт — «Основи інтернету речей та аналітика великих даних»

Репозиторій-заготовка. Тут лежить те, з чого ви починаєте: шаблон
прошивки, каркас конвеєра обробки даних, приклад детектора та інструмент
самоперевірки.

Повне завдання, структура пояснювальної записки, перелік класів
інцидентів і система оцінювання — у
[методичних вказівках](docs/metodychni-vkazivky.md). Цей файл лише
пояснює, як усе запустити.

---

## Що вам видали

| Файл | Що це |
|---|---|
| `variant_NNN.parquet` | **ваш** набір телеметрії, 4,8–7,4 млн записів |
| `variant_NNN.json` | маніфест: перелік пристроїв і призначений стек |
| `tuning.parquet` | навчальний набір, спільний для всіх |
| `tuning_truth.json` | відповіді до навчального набору |

Номер варіанта видає керівник. Файли завантажуються за посиланням із
таблиці призначень.

> Ваш набір даних унікальний. Інциденти у ньому не збігаються з
> інцидентами жодного іншого студента, тому чужі результати вам не
> допоможуть — їх відхилить автоматична перевірка.

## Швидкий старт

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Перевірте, що дані читаються і що маніфест відповідає вашому варіанту:

```bash
python selfcheck.py --findings examples/findings.example.json \
                    --data variant_047.parquet \
                    --manifest variant_047.json
```

Команда надрукує вашу **картку результатів** — ті самі числа, які мають
стояти одразу після титульного аркуша пояснювальної записки. Файл-приклад
складено для навчального набору (варіант 0), тож повідомлення про
розбіжність номера варіанта й картки тут очікувані.

## Стадія 1. Вузол інтернету речей

1. Створіть новий проєкт ESP32 на [wokwi.com](https://wokwi.com)
   (безкоштовного тарифу достатньо).
2. Замініть вміст на `firmware/sketch.ino`, `firmware/diagram.json`
   та `firmware/libraries.txt`.
3. Впишіть свій номер варіанта і `DEVICE_ID` у налаштуваннях на початку
   файла.
4. Запустіть симуляцію. У послідовному моніторі має з'явитися
   підключення до WiFi, синхронізація часу та публікація повідомлень.

Переконайтеся, що повідомлення справді виходять у мережу:

```bash
mosquitto_sub -h broker.hivemq.com -t 'kursova/47/#' -v
```

Чотири позначки `TODO` у прошивці — це і є ваше завдання на стадію.

### Дослідження захищеності каналу

Команда вище — уже половина досліду: ви щойно прочитали чужу (власну)
телеметрію з публічного брокера, не маючи жодних прав на неї. Повторіть
це з іншого комп'ютера, зафіксуйте результат, після чого підніміть на
своєму комп'ютері брокер Mosquitto з TLS та автентифікацією, підключіть
до нього вузол, емульований мовою Python, і повторіть спробу ще раз.
Безкоштовний Wokwi не бачить вашої локальної мережі, тому цей крок
виконується з Python-вузлом — оцінку це не знижує. Усі три спроби
задокументуйте у звіті.

## Стадія 2. Конвеєр

Пакетне завантаження вашого варіанта у призначене сховище:

```python
from pipeline.storage import open_storage

st = open_storage("duckdb", path="telemetry.duckdb")
rows = st.load_parquet("variant_047.parquet")
ts, val = st.series("temp-03-lob", "temperature")
```

Назву сховища беріть із поля `assigned_stack` у вашому маніфесті —
використання призначеного сховища обов'язкове. Рядок звідти можна
передавати дослівно: `open_storage("DuckDB + Parquet", ...)` теж працює.

> **Якщо вам призначено DuckDB.** Типово DuckDB читає Parquet напряму,
> не створюючи власного файла, тому розмір сховища на диску буде нульовим
> і порівнювати в п. 2 стадії 2 буде нічого. Для вимірювань передайте
> `materialise=True` — тоді дані будуть перенесені у файл бази.

Орієнтовні числа на навчальному наборі (1,16 млн записів, 5,3 МБ у
Parquet) — ваші значення залежать від обладнання:

| Сховище | Завантаження | Розмір на диску | Вибірка одного ряду |
|---|---|---|---|
| DuckDB (materialise) | 1,4 млн зап./с | 7 МБ | 0,004 с |
| SQLite | 0,5 млн зап./с | 90 МБ | 0,018 с |

Різниця у розмірі на порядок — не випадковість. Поясніть її у звіті.

Для InfluxDB і TimescaleDB спершу підніміть сервіси:

```bash
docker compose -f pipeline/docker-compose.yml up -d
```

Потоковий вхід:

```bash
python pipeline/consumer.py --variant 47 --device esp32-047 --minutes 10
```

> Ваш файл містить мільйони записів і поки що вміщується в пам'ять, але
> конвеєр має витримувати й обсяги, які в неї не вміщуються. Тому читайте
> порціями — як це робиться, видно у `storage.py`.

маніфесті.

## Стадії 4–5. Реальні дані та пошук

Реальний набір (стадія 4) завантажується окремо:

```bash
curl -O https://db.csail.mit.edu/labdata/data.txt.gz
curl -O https://db.csail.mit.edu/labdata/mote_locs.txt
```

Формат і відомі проблеми цього набору описані у методичних вказівках,
п. 4.4. Еталонних відповідей до нього не існує — висновки обґрунтовуєте
самі.

Результат стадії 5 оформлюється у `findings.json`. **Перед здачею
обов'язково** проженіть його через самоперевірку:

```bash
python selfcheck.py --findings findings.json \
                    --data variant_047.parquet \
                    --manifest variant_047.json
```

Інструмент перевіряє формат і картку результатів. Він **не** повідомляє,
чи правильні ваші знахідки — відповіді є лише у керівника.
