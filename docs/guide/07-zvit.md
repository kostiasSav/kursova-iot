# Крок 7. Пояснювальна записка

**Мета:** описати зроблене так, щоб читач без вашого коду зрозумів, що ви
побудували, що виміряли і що знайшли. Записка дає 20 балів зі 100, а без неї
не зараховується решта.

## 7.1. Обсяг і структура

Обсяг — **25–30 сторінок** без додатків. Менше 20 сторінок — підстава для
оцінки «незадовільно» (п. 8.4 вказівок).

| Частина | Сторінок | Що писати |
|---|---|---|
| Титульний аркуш | 1 | за зразком кафедри |
| Картка результатів | 1 | таблиця з п. 7.2 цього посібника |
| Зміст | 1 | автоматичний зміст редактора |
| Вступ | 2–3 | див. 7.3 |
| Розділ 1. Теоретична частина | 7–8 | див. 7.4 |
| Розділ 2. Проєктування та реалізація | 9–10 | див. 7.5 |
| Розділ 3. Аналіз результатів | 6–7 | див. 7.6 |
| Висновки | 1–2 | див. 7.7 |
| Список використаних джерел | — (не менше 20 джерел) | див. 7.8 |
| Додатки | без обмежень | код, `findings.json`, знімки дашборда |

Оформлення (шрифт, поля, нумерація) — за загальними вимогами кафедри до
курсових робіт. Якщо їх вам не видали, запитайте керівника.

Пишіть у науковому стилі, від третьої особи («у роботі виміряно…», а не
«я виміряв…»). Кожне запозичення — з посиланням у квадратних дужках. Кожне
виміряне число — з умовами вимірювання: обладнання (процесор, пам'ять),
обсяг даних, версії програм (розд. 5 вказівок). Це прямо впливає на оцінку
записки (п. 8.2 вказівок).

**Порада.** Пишіть записку **паралельно** зі стадіями, а не наприкінці: після
кожної стадії одразу переносьте в записку таблиці й рисунки, позначені в
посібнику як «У звіт».

## 7.2. Картка результатів

Розміщується одразу після титульного аркуша. Значення беруться з виводу
`selfcheck.py` (крок 0.7) і з ваших вимірювань. Зразок — для навчального
набору; у вас будуть ваші числа.

| Поле | Значення |
|---|---|
| Варіант | 0 (навчальний набір) |
| Кількість записів | 1 157 147 |
| Пристроїв у маніфесті | 51 |
| Пристроїв у даних | 52 |
| SHA-256 переліку пристроїв | 1a33058d845b45c2ce0ddff78318cad7cab1f1b8c9a25aed2e3cdbafc84b7098 |
| Записів за показниками | див. таблицю нижче |
| Призначений стек | InfluxDB / DuckDB SQL / Matrix Profile / Streamlit |
| Точність / повнота | базовий детектор: … / …; призначений: … / … (стадія 3) |
| Пропускна здатність | … записів/с (стадія 2) |

**Увага.** Картка, що не відповідає виданому варіанту, — підстава для оцінки
«незадовільно». Не набирайте числа вручну: копіюйте їх із виводу програм.

Записи за показниками рахує така команда (замініть файл на свій):

```bash
python -c "import pyarrow.parquet as pq; t = pq.read_table('tuning.parquet').to_pandas(); print(t.groupby('metric', observed=True).size().to_string())"
```

## 7.3. Вступ (2–3 с.)

Дайте відповідь на п'ять питань, по абзацу на кожне:

1. Чому моніторинг пристроїв інтернету речей важливий (масштаб, відмови,
   атаки)?
2. Що є об'єктом і предметом дослідження? (Готові формулювання — у розділі 2
   вказівок.)
3. Яка мета роботи? (Одне речення.)
4. Які завдання ви розв'язали? (Список із 5–7 пунктів, що відповідають
   стадіям.)
5. Що нового у вашій роботі? (Ваш стек, ваші вимірювання, ваші висновки.)

## 7.4. Розділ 1. Теоретична частина (7–8 с.)

Кожен підрозділ — 1–2 сторінки, з посиланнями на джерела у квадратних
дужках, наприклад [3].

- **1.1. Архітектура систем інтернету речей.** Рівні (пристрої, шлюзи,
  мережа, хмара/сховище, застосунки) за ISO/IEC 30141. Де у цій архітектурі
  ваш вузол, брокер, сховище і дашборд.
- **1.2. Протоколи передавання телеметрії та їх захищеність.** MQTT
  (видавець-підписник, брокер, QoS, retain, Last Will), порівняння з CoAP і
  HTTP. Чим небезпечний MQTT без TLS — і посилання на ваш власний досвід зі
  стадії 1.
- **1.3. Характеристики великих даних, архітектури обробки.** «5V»
  (обсяг, швидкість, різноманітність, достовірність, цінність); пакетна і
  потокова обробка; рядкове і стовпцеве зберігання; часові ряди і чому для
  них існують окремі бази (InfluxDB, TimescaleDB).
- **1.4. Методи виявлення аномалій у часових рядах.** Статистичні (z-оцінка,
  медіана/MAD, контрольні карти), декомпозиція (STL), методи на основі
  відстані й щільності (LOF), ізоляції (Isolation Forest), Matrix Profile.
  Окремо — **ваш призначений метод** докладніше. Метрики якості: точність,
  повнота, F1.
- **1.5. Модель загроз пристроїв інтернету речей.** Які загрози стосуються
  розумної будівлі; класи `rogue_device`, `beaconing`, `exfil_pattern` у
  термінах MITRE ATT&CK (джерело 16 у списку вказівок); OWASP IoT Top 10.

## 7.5. Розділ 2. Проєктування та реалізація (9–10 с.)

- **2.1. Обґрунтування архітектури конвеєра.** Схема: вузол → брокер →
  споживач → сховище → обробка → детектори → дашборд. Намалюйте її (draw.io,
  безкоштовно: <https://app.diagrams.net/>). Чому саме такі компоненти.
- **2.2. Реалізація вузла та протоколу передавання.** Схема підключення у
  Wokwi, формат повідомлення (Додаток А вказівок), Last Will, вимірювання JSON
  проти CBOR, результати дослідження захищеності каналу зі знімками.
- **2.3. Організація зберігання даних.** Ваше сховище: модель даних
  (таблиця/вимірювання, поля, індекси), як завантажуєте, де межа пам'яті і як
  ви її обходите.
- **2.4. Реалізація детекторів.** Базовий і призначений детектор: ідея,
  параметри, як ви їх підібрали на навчальному наборі.

Код у тексті — лише короткими фрагментами (до 10–15 рядків). Повний код —
у додатках і в репозиторії.

## 7.6. Розділ 3. Аналіз результатів (6–7 с.)

- **3.1. Показники продуктивності конвеєра.** Таблиця вимірювань зі
  стадії 2 (розмір CSV/Parquet, стиснення, швидкість завантаження, час
  сканування і вибірки, пам'ять) з описом комп'ютера, на якому міряли.
- **3.2. Порівняння детекторів за точністю та повнотою.** Таблиця зі стадії 3;
  результати на реальних даних зі стадії 4: проблеми даних, вжиті заходи,
  зміна кількості хибних спрацювань.
- **3.3. Виявлені інциденти та методика їх встановлення.** Таблиця ваших
  знахідок (пристрої, час, клас, упевненість) і для кожної — **на основі чого**
  ви дійшли висновку, з рисунком.
- **3.4. Недоліки рішення та напрями вдосконалення.** Чесно: що не вийшло,
  які класи не знаходяться і чому, що зробили б інакше.

## 7.7. Висновки (1–2 с.)

По одному абзацу на кожне завдання зі вступу, з **числами**: «стовпцеве
зберігання зменшило обсяг у … разів», «призначений детектор досяг повноти …
на навчальному наборі», «у варіанті виявлено … інцидентів, з них … —
складних». Без нових фактів, яких немає в розділах.

## 7.8. Список використаних джерел

Не менше 20 джерел, зокрема матеріали конференцій IEEE і чинні стандарти.
Перші 18 можна взяти з розділу 10 вказівок, решту доберіть самі. Оформлення —
за ДСТУ 8302:2015. Зразки:

```
1. ISO/IEC 30141:2024. Internet of Things (IoT) — Reference architecture.
   Geneva : ISO, 2024.
2. Liu F. T., Ting K. M., Zhou Z.-H. Isolation Forest. 2008 Eighth IEEE
   International Conference on Data Mining. Pisa, 2008. P. 413–422.
3. Rosner B. Percentage Points for a Generalized ESD Many-Outlier Procedure.
   Technometrics. 1983. Vol. 25, no. 2. P. 165–172.
4. Intel Berkeley Research Lab sensor data. URL:
   https://db.csail.mit.edu/labdata/labdata.html (дата звернення: 01.11.2026).
```

**Увага.** Набір даних Intel Lab **обов'язково** має бути у списку джерел
(умова його використання).

## Типові помилки

- Картка результатів набрана вручну з помилкою — **«незадовільно»**.
- Таблиці без підписів і без посилань на них у тексті.
- Знімки екрана, на яких нічого не видно: обрізайте до потрібної частини.
- Теоретична частина, переписана з джерел без посилань.
- Висновки без жодного числа.
- Список джерел із самих вебсторінок.
