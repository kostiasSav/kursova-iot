# Крок 8. Захист

**Мета:** показати, що проєкт ваш і що він працює. Захист — 10 балів, але
головне інше: якщо ваш конвеєр не запуститься на незнайомих даних, це
**«незадовільно» незалежно від решти** (п. 8.3 вказівок).

## 8.1. Що буде на захисті

1. **Доповідь до 7 хвилин** з показом працездатного дашборда.
2. **Демонстрація вузла** (складник «Вузол IoT, MQTT, захищеність каналу»
   оцінюють саме так): вузол у Wokwi, що публікує повідомлення (потрібен
   інтернет), і ваш власний брокер з TLS разом із `node/node.py` (працює без
   інтернету).
3. **Запуск на незнайомих даних.** Вам дадуть набір даних, якого ви ніколи
   не бачили (файли `variant_1NN.parquet` і `variant_1NN.json`, такого самого
   формату, як ваш варіант), і попросять запустити ваш конвеєр при комісії:
   завантажити дані у **ваше** сховище, прогнати пошук і отримати перелік
   знахідок.
4. **Запитання** — про ваш код, ваші рішення і ваші числа.

Приносьте **свій** ноутбук з усім установленим. Інтернету на захисті може не
бути — перевірте, що все працює без нього (крім Wokwi). На випадок, якщо
Wokwi не відкриється, майте знімки екрана або коротке відео роботи вузла.

## 8.2. Один скрипт для всього

Щоб запуск при комісії зайняв хвилини, а не пів години, усі кроки зведено в
один скрипт `run_all.py` — він уже є в заготовці:

```bash
python run_all.py --data variant_1NN.parquet --manifest variant_1NN.json --storage duckdb
```

Замість `duckdb` вкажіть **своє** сховище — те, що записане у вашому
`variant_NNN.json` (`duckdb`, `sqlite`, `influxdb` або `timescaledb`). У
маніфесті незнайомого набору призначено чужий стек; скрипт про це
повідомить, але працюватиме з вашим сховищем, як і має бути.

Скрипт по черзі:

1. завантажує дані у ваше сховище;
2. друкує картку результатів — числа з вашого сховища;
3. шукає інциденти — **вашою** функцією `find_incidents` з файла `hunt.py`;
4. записує `findings.json`, перевіряє його через `selfcheck.py` і друкує,
   скільки знахідок кожного класу.

Кроки 1, 2 і 4 готові. Крок 3 — ваша робота.

### Ваш `hunt.py`

На стадії 5 ви шукали інциденти, переглядаючи графіки й записуючи знахідки в
таблицю. Для захисту той самий пошук має стати **кодом**: на незнайомих даних
таблиці, складеної вручну, у вас не буде.

Якщо файла `hunt.py` ще немає, `run_all.py` надрукує заготовку:

```python
def find_incidents(storage, manifest):
    """storage — відкрите й заповнене сховище; manifest — маніфест (словник)."""
    findings = []
    # Приклад одного запису:
    # findings.append({
    #     "devices": ["temp-03-lob"],
    #     "class": "stuck_at",
    #     "start": "2025-09-14T08:30:00Z",
    #     "end": "2025-09-14T16:00:00Z",
    #     "confidence": 0.8,
    #     "evidence": "температура не змінювалася 7,5 год",
    # })
    return findings
```

Збережіть її у файл `hunt.py` поруч із `run_all.py` і наповніть. Усередині
функції вам доступні:

| Що | Як отримати |
|---|---|
| перелік пристроїв у даних | `storage.devices()` |
| перелік показників | `storage.metrics()` |
| ряд одного пристрою | `ts, val = storage.series("temp-03-lob", "temperature")` — масиви часу (секунди UTC) і значень |
| пристрої з маніфесту, їхні зони й шлюзи | `manifest["devices"]` |

Знахідки — ті самі поля, що й у `my_findings.csv` зі стадії 5. Найпростіший
шлях: для кожного класу, який ви знаходили, перенесіть у функцію ті самі
правила, за якими ви вирішували вручну (пороги, вікна, порівняння з
сусідами), і перевірте на навчальному наборі, що вона знаходить відомі
інциденти з `tuning_truth.json`.

### Перевірка на навчальному наборі

У `tuning.json` призначено InfluxDB, тому для репетиції вкажіть **своє**
сховище ключем `--storage` (тут — DuckDB):

```bash
python run_all.py --data tuning.parquet --manifest tuning.json --storage duckdb
```

бачили вище, пропущено):

## 8.3. Репетиція

За тиждень до захисту зробіть повну репетицію, ніби ви вже при комісії:

- [ ] Перезавантажте комп'ютер (щоб нічого не лишилося «запущеним випадково»).
- [ ] Якщо ваше сховище — InfluxDB чи TimescaleDB: запустіть Docker Desktop і
      переконайтеся, що контейнери піднімаються командою зі стадії 2.
- [ ] Активуйте віртуальне середовище.
- [ ] Запустіть `run_all.py` на **навчальному наборі** з `--storage` вашого
      сховища (команда з 8.2) — він має пройти від початку до кінця без
      жодного втручання і знайти відомі інциденти.
- [ ] Засічіть час. Якщо довше 10 хвилин — подумайте, що прискорити.
- [ ] Запустіть дашборд і пройдіть по всіх його частинах. Для Grafana спершу
      перезавантажте у сховище свій варіант: `run_all.py` замінив його
      навчальним набором (команда — у 6.4, з ключем `--reload`).
- [ ] Покажіть самі собі вузол: Wokwi і власний брокер з `node.py`.
- [ ] Вимкніть Wi-Fi і повторіть — чи нічого не залежить від інтернету?

**Увага.** Найчастіша причина провалу — не код, а середовище: Docker не
запущений, віртуальне середовище не активоване, файл лежить не в тій папці.
Репетиція знаходить саме ці проблеми.

## 8.4. Доповідь на 7 хвилин

Приблизно один слайд на хвилину:

| Хв | Слайд |
|---|---|

## 8.5. Запитання, які часто ставлять

- Чому для цього класу інцидентів ви обрали саме такий детектор?
- Що станеться з вашим конвеєром, якщо даних буде в 100 разів більше?
- Покажіть у коді, де ви рахуєте точність і повноту.
- Чому ця знахідка — `sensor_swap`, а не два окремі `drift`?
- Що бачив сторонній клієнт до TLS і що — після?
- Як ви перевіряли, що спрацювання на даних Intel Lab хибні?

Відповідати треба своїми словами і з вашими числами. Знати напам'ять
формули не обов'язково, а розуміти, що робить ваш код, — обов'язково.
